Zero-Friction Onboarding

I1
Zero-Friction Onboarding
Get a team from sign-up to a live pipeline view in under 5 minutes
Reduce every barrier between a new user and a functioning pipeline visualisation. One-click OAuth for Jira and GitHub, automatic workspace creation, guided first-run experience, and a demo mode populated with sample data so the product sells itself before any integration is connected.
Targeted Objectives & Key Results
O1 KR 1.1 Grow registered users — frictionless sign-up drives top-of-funnel volume ↑ +500 users
O1 KR 1.2 Grow active workspaces — guided setup converts sign-ups into connected teams ↑ +100 workspaces
O1 KR 1.3 Improve NPS — a smooth first experience drives positive sentiment ≥ NPS 40
Features & Deliverables
⚡
One-click OAuth Integration
Single-click connect for Jira and GitHub via OAuth. No manual API key configuration. Workspace auto-detects available projects and repos.
Integration
★
Interactive Demo Mode
Pre-populated sample pipeline with animated tickets flowing through stages. Available instantly on sign-up before any integration is connected. Shows the full product value proposition.
Frontend
✓
Guided First-Run Experience
Step-by-step onboarding flow: connect Jira, connect GitHub, see your first live ticket appear. Progress indicators and contextual tooltips.
Design
⚙
Auto-Workspace Provisioning
Workspace created automatically on sign-up with sensible defaults. No manual configuration required. Architecture pane pre-configured based on detected repo structure.

02

Real-time Pipeline View

I2
Real-time Pipeline View
The core 3D scene that makes pipeline state spatially visible and always live
Build the foundational 3D pipeline view that delivers the core value proposition. Tickets appear as boxes, flow through stages, and land on environment panes — all updated in real time via WebSocket. This is the feature that keeps users coming back daily.
Targeted Objectives & Key Results
O2 KR 2.1 Increase DAU/MAU ratio — a live, useful view drives daily return visits ↑ +40% DAU/MAU
O2 KR 2.2 Increase session duration — an ambient view encourages longer passive observation ↑ +25% avg duration
O4 KR 4.1 Increase pipeline visibility score — spatial representation improves situational awareness ↑ +60% avg score
O2 KR 2.4 Reduce monthly churn — daily utility prevents cancellation ↓ <5% monthly churn
Features & Deliverables
█
3D Ticket Boxes
Jira tickets rendered as floating 3D boxes. Colour encodes priority, size encodes story points. Labels show ticket key and summary. Grouped loosely by epic.
Frontend
⟶
Stage Transition Animations
Smooth animations as tickets move between pipeline stages. Boxes float toward Claude agent, transform into build artifacts, arc toward environment panes. Spring-based physics via XState.
Frontend
▦
Environment Pane Renderer
Semi-transparent vertical planes for test and production. Architecture components (API, DB, Worker, CDN) as opaque cards. Components light up green on successful deploy, red on failure.
Frontend
⇄
WebSocket State Sync
Bidirectional WebSocket connection from frontend to orchestration server. Pipeline state pushed on every change. Reconnect with exponential backoff. Delta compression for efficiency.
Backend
🔍
Ticket Inspection Panel
Click or gaze at a ticket box to open a detail panel showing full Jira data: description, assignee, linked PR, CI status, deploy history. Works in both desktop and VR.
Frontend
03

Bottleneck Detection

I3
Bottleneck Detection & Alerting
Make stuck builds, failed deploys, and stalled PRs immediately visible
Automatically detect when features stall at any pipeline stage and make the blockage visually prominent in the 3D scene. Tickets stuck in CI glow red. Failed deployments trigger visual and optional audio alerts. The spatial view turns bottlenecks from invisible into unmissable.
Targeted Objectives & Key Results
O4 KR 4.2 Increase bottleneck detection rate within 15 minutes of occurrence ↑ +50% detection in 15min
O4 KR 4.1 Increase pipeline visibility score — proactive alerts improve confidence ↑ +60% avg score
O2 KR 2.1 Increase DAU/MAU — alerts create a reason to check the view daily ↑ +40% DAU/MAU
Features & Deliverables
⚠
Stall Detection Engine
Backend service that monitors time-in-stage for every feature. Configurable thresholds per stage (e.g. building > 30min, review > 4h). Emits alert events to WebSocket.
Backend
✕
Visual Alert States
Blocked tickets pulse red with a glow effect. Failed deploys flash the affected component on the environment pane. Stalled PRs show a warning indicator orbiting the build artifact.
Frontend
♫
Spatial Audio Alerts
Optional audio cues for alert events in VR mode. Directional audio positioned at the blocked ticket so the user can hear where the problem is. Configurable per-alert-type.
Frontend
✉
External Notifications
Push blocked/failed alerts to Slack, email, or webhook. Links back to the 3D view focused on the specific blocked item. Configurable per workspace.

04

Immersive VR Experience

I4
Immersive VR Experience
Full WebXR support with hand tracking, room-scale, and spatial interaction
Elevate the desktop 3D view into a true immersive VR experience. Hand tracking for natural interaction, room-scale so users can walk through their pipeline, and gaze-based inspection for zero-friction detail views. This is the differentiator that no competitor can replicate in a 2D dashboard.
Targeted Objectives & Key Results
O2 KR 2.3 Grow VR session adoption rate — a compelling VR experience justifies the hardware ↑ +15% VR sessions
O2 KR 2.2 Increase session duration — immersion extends observation time ↑ +25% avg duration
O1 KR 1.3 Improve NPS — VR experience creates strong positive sentiment and word-of-mouth ≥ NPS 40
Features & Deliverables
☞
Hand Tracking & Controller Input
Full hand tracking support for Quest and Vision Pro. Pinch-to-select tickets, grab-to-rotate the scene, point-to-inspect. Fallback to controller input on devices without hand tracking.
Frontend
↔
Room-Scale Scene Layout
Pipeline zones mapped to physical room space. Walk toward the backlog to see ticket detail. Step into the centre to observe Claude working. Approach environment panes to inspect deployed components.
Frontend
☉
Gaze-to-Inspect
Look at any ticket or component for 1.5 seconds to open its detail panel. Natural, hands-free interaction for passive monitoring. Visual focus indicator during dwell.
Frontend
☁
VR UI Panels
Floating UI panels in VR space for settings, workspace switching, and integration status. Positioned ergonomically at wrist level. Follows the user on teleport.

05

Team Workspaces

I5
Team Workspaces & Shared Spaces
Multi-user observation, team management, and shared pipeline views
Enable teams to share a single pipeline view. Multiple users can observe the same workspace simultaneously, see each other's cursors or avatars, and use the shared view in standups and stakeholder demos. This is the feature that drives team-level adoption and the upgrade from free to paid.
Targeted Objectives & Key Results
O3 KR 3.2 Increase free-to-paid conversion — shared spaces are the primary paid feature ↑ +8% conversion
O3 KR 3.1 Grow MRR — team subscriptions are the primary revenue driver ↑ £5,000 MRR
O3 KR 3.3 Reduce paid churn — team adoption creates stickiness ↓ <3% paid churn
O1 KR 1.2 Grow active workspaces — team features expand from individual to team adoption ↑ +100 workspaces
Features & Deliverables
☻
Multi-User Presence
See other team members in the shared view. Desktop: coloured cursors with name labels. VR: avatar heads and hand positions. Presence state synced via WebSocket.
Frontend
⚙
Workspace Management
Invite team members by email. Role-based access (admin, member, viewer). Workspace settings for alert thresholds, integration config, and architecture layout.
Backend
☰
Multi-Repo View
Connect multiple repositories to a single workspace. Each repo's pipeline is spatially separated but visible in the same scene. Zoom into a single repo or observe all at once.
Frontend
✎
Standup Mode
One-click standup view that highlights what shipped yesterday, what's in progress today, and what's blocked. Optimised for screen-sharing and VR group observation.

06

Integration Ecosystem

I6
Integration Ecosystem Expansion
Support the full range of tools used by target market teams
Expand beyond Jira + GitHub to cover Linear, GitLab, Azure DevOps, ArgoCD, Vercel, and more. Each new connector removes an adoption barrier for teams using non-default stacks. A plugin architecture allows community-contributed connectors.
Targeted Objectives & Key Results
O5 KR 5.1 Reach 10+ supported integrations covering the top tools in the target market ≥ 10 integrations
O4 KR 4.3 Increase avg integrations per workspace — more connectors means richer views ↑ +3 avg integrations
O5 KR 5.2 Grow active workspaces QoQ — broader support opens new market segments ↑ +80% workspaces QoQ
O5 KR 5.3 Grow registered users QoQ — integration breadth drives organic discovery ↑ +200% users QoQ
Features & Deliverables
⚙
Connector Plugin Architecture
Standard connector interface with normalise(event) → PipelineEvent contract. New integrations implemented as isolated plugins with their own auth, polling, and webhook handlers.
Backend
✚
Linear Connector
Full ticket lifecycle from Linear: issues, status transitions, labels, cycles. Maps to backlog boxes with Linear's priority and estimate fields.
Integration
✚
GitLab CI Connector
Pipeline runs, merge requests, and deployment events from GitLab. Maps to build transitions and environment pane state.
Integration
✚
Vercel / Netlify Deploy Connector
Deployment status from Vercel and Netlify. Maps preview deploys to test pane and production deploys to production pane.
Integration
✚
ArgoCD / Kubernetes Connector
Sync status, rollout progress, and health checks from ArgoCD. Maps directly to environment pane components with real-time health indicators.

Monetisation & Tiers

I7
Monetisation & Pricing Tiers
Free individual tier, paid team tier, enterprise custom — the revenue engine
Implement the tiered pricing model that converts free adoption into sustainable revenue. The free tier covers individual use with a single project. The team tier unlocks shared workspaces, multi-repo views, and advanced alerts. Enterprise adds SSO, audit logs, and SLA-backed support.
Targeted Objectives & Key Results
O3 KR 3.1 Grow MRR to £5,000 — tier structure is the primary revenue mechanism ↑ £5,000 MRR
O3 KR 3.2 Increase free-to-paid conversion — clear value differentiation between tiers ↑ +8% conversion
O3 KR 3.3 Reduce paid churn — enterprise features and SLAs create long-term contracts ↓ <3% paid churn
Features & Deliverables
★
Billing & Subscription Management
Stripe integration for subscription billing. Self-serve upgrade/downgrade. Usage-based billing for enterprise. Invoice generation and payment history.
Infra
☍
Feature Gating
Tier-based feature flags: shared workspaces (team+), multi-repo (team+), advanced alerts (team+), SSO (enterprise), audit log (enterprise). Graceful upgrade prompts in-app.
Backend
⚡
Upgrade Prompts & Trial
Contextual upgrade prompts when users hit free-tier limits. 14-day free trial of team tier. Usage analytics to identify high-value free users for targeted outreach.
Growth
⚠
Enterprise SSO & Audit
SAML/OIDC SSO for enterprise customers. Full audit log of workspace access, integration changes, and configuration modifications. SOC 2 readiness.
