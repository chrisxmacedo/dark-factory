01

Identified Problems

The following problems have been observed in development teams operating with AI-assisted automation pipelines. Each problem is independently verifiable and contributes to the overall case for a spatial, real-time pipeline visualisation tool.

1
Fragmented Visibility
Pipeline state is distributed across Jira, GitHub, and deployment dashboards. Understanding the current status of any single feature requires checking three or more disconnected interfaces. There is no unified view.
2
Context Switching Overhead
Developers and managers lose significant time switching between tools to answer basic questions: “What is being worked on?”, “What is blocked?”, “What deployed today?”. Each context switch carries a cognitive cost that compounds across the team.
3
Invisible Bottlenecks
A feature stuck in CI, a PR waiting on review, a deployment that failed silently — these states are indistinguishable without actively querying each system. Bottlenecks go unnoticed until someone asks or a deadline is missed.
4
No Passive Monitoring
Existing dashboards require active reading and interpretation. There is no ambient, always-on representation of pipeline health that can be passively observed — the way a factory floor or air traffic control screen provides at-a-glance awareness.
5
AI Automation Opacity
As AI agents (Claude, Copilot) handle more of the development lifecycle autonomously, the human operator's role shifts from doing to supervising. But there is no supervisory interface designed for this mode of operation — existing tools assume the human is the primary actor.
6
Reporting Requires Manual Aggregation
Producing a coherent picture of pipeline throughput, deployment frequency, or sprint velocity requires manually pulling data from multiple systems and assembling it into reports. This is time-consuming and the output is always stale by the time it is shared.
7
Stakeholder Communication Gap
Non-technical stakeholders cannot meaningfully interpret Jira boards, GitHub PR lists, or CI/CD logs. There is no representation of the delivery pipeline that is accessible to people outside the engineering team without explanation.
02

Problem Statement

Problem Statement
Development teams using AI-assisted automation have no unified, real-time, spatial view of their delivery pipeline. Pipeline state is fragmented across disconnected tools, bottlenecks are invisible without active investigation, and the shift from human-driven to AI-driven development has created a supervisory gap — operators need to observe and intervene, but existing interfaces are designed for direct participation, not oversight.
03

Vision

Vision Statement
A persistent, immersive 3D environment where the entire software delivery lifecycle — from ticket to production — is spatially visible, always live, and immediately intuitive. Features flow through the space as physical objects: consumed by AI agents, transformed into builds, and deployed onto environment surfaces. The pipeline becomes something you watch, not something you query — an operational control room for AI-augmented software delivery.
  • The vision prioritises passive observation over active interaction — the default state is watching, not clicking
  • The spatial metaphor is not decorative — position, movement, and visual state encode meaningful pipeline data
  • The system must work at the speed of the pipeline — real-time updates, not polling intervals
  • Accessibility is non-negotiable — the full experience must work on desktop browsers without VR hardware
  • The product is designed for the emerging reality of AI-first development where humans supervise, not execute
