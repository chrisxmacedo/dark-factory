Mandatory Service Instrumentation

Every service in every environment must satisfy these six requirements. Enforced by {INSTRUMENTATION_LIBRARY} at startup — missing fields cause startup failure.

Structured Logging — JSON only to stdout. Mandatory base schema: timestamp, level, service, version, environment, trace_id, span_id, message. No plain text logging.
Distributed Tracing — OTel SDK with service.name, service.version, deployment.environment. All HTTP handlers/clients wrapped. {MESSAGE_BUS_NAME} producers inject traceparent; consumers extract and create child spans. DB queries traced with sanitised SQL.
Prometheus Metrics — /metrics endpoint on every service. Mandatory labels: service, version, environment. Required: {METRIC_HISTOGRAM_NAME} histogram, {METRIC_CONSUMER_LAG_NAME} per topic/partition, {METRIC_SECRET_EXPIRY_NAME} per secret. No entity IDs as labels.
Health Endpoints — Three distinct, never conflated: GET /healthz (liveness only, no deps), GET /readyz (checks DB, consumer lag, critical deps; returns 503 if unavailable), GET /infoz (service name, version, commit SHA, build timestamp; unauthenticated, rate-limited).
{EVENT_ENVELOPE_STANDARD} Envelope — All messages carry headers: specversion, type (reverse-DNS), source, id (UUIDv4), time, traceparent. Producers and consumers log the envelope id for end-to-end correlation.
service.yaml Manifest — Machine-readable per-repo manifest: id, tier, depends_on (protocol + criticality: hard/soft), topics_produced, topics_consumed, data_classification ({DATA_CLASS_LEVELS}), secrets with rotation_days.
