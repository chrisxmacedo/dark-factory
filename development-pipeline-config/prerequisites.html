GitHub Organisation

Repository Setup

Create a GitHub organisation for your project. All repos must be created under this org, never under personal accounts. This prevents agents from accidentally pushing to the wrong location.

Each service in your project gets its own standalone git repo under the org. Do not use a monorepo — each service directory must be its own git repository with its own branches, PRs, and CI configuration.

Example structure:

your-org/
    your-project-api — standalone git repo
    your-project-web — standalone git repo
    your-project-scraper — standalone git repo

Claude Code Permissions

Settings Configuration

Your ~/.claude/settings.json should allow bash commands and compound git operations. The pipeline's agent teams need to run git, test runners, and linters without being blocked by permission prompts.

Recommended permissions configuration:

{
  "permissions": {
    "allow": [
      "Bash(*)",
      "Bash(cd:*)"
    ],
    "deny": [
      "Bash(*git reset --hard*)",
      "Bash(*git push --force*)",
      "Bash(*rm -rf*)"
    ]
  }
}

The deny rules prevent destructive operations while allowing all standard development commands.

Atlassian MCP Connection

Connecting Claude to Jira

The Atlassian MCP (Model Context Protocol) server allows Claude Code to read and write Jira tickets directly. This is what enables the Team Lead to poll for tickets, transition statuses, and add comments.

  1. In Claude Code, connect the Atlassian MCP server
  2. Authenticate with your Atlassian account
  3. Grant read:jira-work and write:jira-work permissions
  4. Run getAccessibleAtlassianResources to find your Cloud ID
  5. Note the Cloud ID — you will need it when configuring the pipeline
