Claude Code Setup Installing starter templates and configuring the Team Lead

Step 1 — Copy Starter Templates

File Structure

Copy the contents of templates/starter-delivery-team/development-team/ into your project's workspace directory. The key files are:

your-project/
    .claude/
        CLAUDE.md — copied from PIPELINE.md, with placeholders replaced
        agents/
            development-team.md
            local-test-team.md
            integration-test-team.md
            e2e-impact-team.md
            regression-team.md
            release-team.md
    platform.md — external service inventory
    workflow-improvements.md — retrospective log
    your-service-api/ — standalone git repo
    your-service-web/ — standalone git repo

Step 2 — Replace Placeholders

Configuration Values

Open PIPELINE.md and replace all placeholder values. The template uses the following placeholders:

PlaceholderReplace WithExample
{PROJECT_NAME}Your project's full nameAcme Platform
{PROJECT_KEY}Your Jira project keyACM
{CLOUD_ID}Your Atlassian Cloud ID (UUID)4c185920-0898-...
{JIRA_URL}Your Jira instance URLhttps://yourname.atlassian.net

After replacement, rename PIPELINE.md to .claude/CLAUDE.md. This is the file Claude Code reads as its system instructions when launched from this directory.

Step 3 — Update Transition IDs

Transition Table

In CLAUDE.md, find the transition table section (all values marked TBC) and replace each with the actual transition ID you retrieved from Jira in the previous step.

This table is critical — if the IDs are wrong, the Team Lead cannot transition tickets between statuses.

Step 4 — Update Polling Queries

Status Name Alignment

The polling queries in CLAUDE.md use status names like "Ready for Dev". If your Jira uses different names (e.g. "Selected for Development"), update the JQL queries to match exactly.

Run a test query in Jira to verify:

project = PRJ AND status = "Ready for Dev" ORDER BY priority ASC

If this returns no results but tickets exist in that status, the name doesn't match.

Step 5 — Create Supporting Files

Platform File

Create a platform.md in your project workspace documenting all external services, their purpose, environment variables, and configuration. Update this file whenever a service is added or changed.

Workflow Improvements Log

Create an empty workflow-improvements.md in your project workspace. The Team Lead appends retrospective entries here after each pipeline stage completes. Over time this becomes a living record of how the pipeline evolved.

Step 6 — Initialise Git Branches

Branch Setup

For each service repo, create the two permanent branches:

# In each service repo
git checkout -b main
git push -u origin main

git checkout -b ci
git push -u origin ci

The main branch is production. The ci branch is the integration branch where feature branches are merged. Feature branches and release branches are created by the Team Lead as needed.

Step 7 — Launch

Starting the Team Lead

Navigate to your project workspace directory and launch Claude Code:

cd /path/to/your-project
claude

Claude Code reads .claude/CLAUDE.md and becomes the Team Lead. It will begin polling Jira for tickets in the pipeline statuses. Move a Deliverable to "Ready for Dev" in Jira to trigger the first run.

Checklist

  • PIPELINE.md renamed to .claude/CLAUDE.md
  • All 6 agent files in .claude/agents/
  • Transition IDs populated (no TBC values remaining)
  • Polling query status names verified against Jira
  • platform.md created
  • workflow-improvements.md created
  • main and ci branches initialised in each service repo
  • Claude Code launched and Team Lead active
